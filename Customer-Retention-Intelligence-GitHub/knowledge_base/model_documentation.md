# Customer Churn Model Documentation
## Project
Customer Retention Intelligence
## Objective 
The model estimates the probability that a telecom customer will churn.
The output is a probability between 0 and 1
For example:
0.20 means the model assigns approximately 20% churn probability to that customer.
The probability is a model prediction and should not be interpreted ass a gurantee
that the customer will or will not churn.
#Advanced Model
The main model is a deep-learning model designed for tabular customer data.
It uses: 
- Numerical feature normalization
- Categorical feature lookup 
- Categorical embeddings
- Features concantenation
- Batch normalization
- Dense neural-network layers
- Dropout
- Sigmoid output

The model was trained using class weighting because churn is less common
than non-churn in the datasest
## Training Controls
The training process uses:
- Training validation and test splits
- Early Stopping
- Learning-rate reduction
- Best-model checkpointing
The final test set is reserved for final evaluation.
## Model Evaluation 
The project evaluates the model using several measures rather than accuracy
alone:
- Accuracy 
- Precision
- Recall 
- F1 Score
- ROC-AUC
- PR-AUC
Recall is particularly usefull when considering churn detection because missing
a genuinely at-risk customer can be important for a retention wokflow.
## Explainability
SHAP is used to understand how individual features influence model predictions.
A positive SHAP value means that the feature pushed the model prediction toward
higher churn probability for the customer being explained.
A negative SHAP value means that the feature pushed the model prediction 
toward lower churn propability.
SHAP describes model behavior. It does not establish that a feature causes
churn.
## Risk Bands
The project uses three practical risk bands:
- Low: below 30%
- Medium: 30% to below 60%
- High: 60% or above
These thresholds are project-defined and can be changes later based on business
requirements.
## Important Limitation
The churn model predicts risk from historical customer data.
It does not estimate the casual effect of a retention action.
Therefore, recommendations generated by the retention layer should be treated
as decision-support suggestions rather than guaranteed methods of preventing churn.
